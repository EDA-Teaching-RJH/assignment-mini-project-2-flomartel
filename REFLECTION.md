**Developer Journal for Film Watchlist Project**
For this assignment I decided to make a film organisation and rating system, as this is of high interest for me because I love watching and reviewing films. 


**OBJECT-ORIENTED PROGRAMMING**
My two classes are Watchlist and Film. The Film class I created first within the film.py file. This class represents a singular film when it is added by the user through the main menu when the main_project_file.py is run. When a new film object is created at this point, the init constructor method “ __init__”  is used to initialise the attributes Title, Year, and Genre. I also added two other attributes which were watched = False and rating = None. The main project file will create this film object through option 3.Add Film to Watchlist, this is done through "from film import Film" and " from watchlist import Watchlist". After the main file creates the film object this is then sent to my Watchlist class under a new file called watchlist.py (through the code watchlist.add_film(film)). The watchlist.py file manages all of my films and provides all of the functionality when the user interacts with the main menu. This demonstrates the use of Object-Oriented Programming by organising the program into clearly defined classes under different files. The Film object represents individual films, and the Watchlist class manages the whole collection of these objects. This was introduced in lecture 9, specifically slide 16 where it is shown how to set up a class. I then slightly expanded on this and changed my film class to use inheritance, which is covered in the same lecture, and slide 24 was the most helpful to my work. I created the "Cinema" superclass with the attributes of title and year. I then made the original "Film" class from before inherit these two attributes from the superclass, but added genre, watched status and rating.

**REGEX**
I used two different REGEX filters for validating data input by the user. I learnt most of the skills I used here in workshop 8, where we had to validate an email adress. I also used this workshop to refresh my mind on the core REGEX symbols for filtering data. I first used regex to validate the year of the film, making sure that the first number is either 19 or 20, and then is followed by two numbers after that. This used the filter '(r"^(19|20)\d{2}$", Year)'. My second filter for REGEX implementation was the film rating validation. I wanted to make sure that the user could input a decimal number or integer 0-5. This meant I had to use float() to convert the integer into a floating point number (deicmal). For both of these I also made sure that if the number entered was found wrong, instead of crashing the code it would loop and ask the user for a valid input until they did.

I used this first to read from my recommendations.csv and then later on when I implemented the reading and writing all films with my watchlist.csv so that they are remembered even after the user exits and plays the program again. I also implemented my own custom libraries (film.py and watchlist.py) after referring to the lecture 7 slide 17 titled "Your own library". **TESTING**
I tested all of my coded functions throughout the project, making sure that the code ran as needed, and in cases where the program could crash. I anticipated any edge cases such as the user implementing a number not deemed valid by the REGEX filter, for example by saying "Please enter a valid year: " and asking the user to reinput. This will loop until a valid input is entered instead of crashing the code. I also did this within the main menu incase the user inputs an option not 1-7.

I extended my project slightly further, implementing a filter that makes sure the user cannot add the same film twice to their watchlist, which just means that the program functions slightly more intuitively and is more user friendly, so that the watchlist.csv doesn't get filled up with repeat films. This also means that if a user accidentally entered the same film twice into their watchlist then tried to set one as watched and rated, the program wouldn't get confused of which one to set to watched = true.
